## Question

依据已确认的完整 TO、C01—C17 能力链和[完整健康管家当前能力与约束报告](../evidence/28-complete-current-capability-and-constraint-report-20260820.md)，为目标 Partner Hermes 中实际部署的健康管家 Plugin 选择一条统一、可实施、可验证且没有竞争权威的技术路线。不得把入口、画像、任务、模型、安全、删除和运行状态拆成彼此独立却无法组合的局部 HOW，也不得直接复用完整 CAN 已排除的旧候选路线。

AI 必须基于完整 CAN 自行给出一条推荐的端到端技术路线，并用下面的场景解释为什么这样选；不能把九个技术栏目逐项抛给主人确认。只有发现会改变既定产品承诺、风险接受或不可逆外部授权的选择时，才向主人提出具体场景化问题并暂停相应决定。

本票必须用贯穿同一位主人的具体旅程来对齐技术选择，而不是先让主人确认抽象模块名。例如：健康管家尚未初始化时主人发来健康内容；初始化完成后主人说“夜班让我只睡了四小时”；相同消息重复到达；每日复盘生成一项任务；选定首发诊断范围后，主人资料缺关键项时不形成诊断、补齐后才产生范围内结果，出现范围外或危险线索、安全组件不可用时分别失败关闭，来源失效或主人纠正后旧判断退出当前并触发必要通知；首跳路线变化、容量或结构终态无法证明；一次模型或微信调用结果未知；停机错过复盘；主人暂停主动支持、停止新增记录、撤回外部执行批准或永久删除；删除后旧 VM 又恢复；健康管家随后迁移到另一台 Hermes。每个场景都要说明请求经过哪些权威边界、哪些对象被读取或写入、谁有最终决定权、主人看到什么、失败或未知怎样保持真实，以及旧状态为什么不能复活。

至少必须一次性选择并闭合以下互相依赖的路线：

1. **运行拓扑与可信边界**：健康 Plugin、Partner Hermes Gateway、微信接入、内部自动流程及任何辅助进程怎样组织；哪些失败必须使健康能力失败关闭；如何避免依赖 fail-open 的通用 Hook、Middleware、提示词或模型自律。
2. **初始化与入口收敛**：健康初始化的完整提交边界在哪里；微信逐次来源在内置去重、合批或 cursor 丢失信息之前怎样接管；Telegram、普通 Agent、Tool、Command、Cron 和其他内部路径如何不能旁路健康门禁。必须把初始化、主人询问、画像更新与导出、任务查看与控制、行为设置、永久删除、运行状态查询及自动复盘逐项映射到自然语言、Skill、Tool、Command 或内部流程，并解释模型没有调用 Tool 时为什么也不能旁路权威边界。
3. **单一权威状态与对象关系**：画像顶部当前状态、六个固定一级域与固定基础二级主题如何表示，新增或改变二级主题如何先取得主人同意；一个逻辑证据库如何按个人健康证据、通用权威知识、任务过程证据三类，再按六域索引到最小证据卡，画像与任务只引用同一权威卡，AI 如何按当前目的最小读取而不形成超大文档。画像、证据、任务、批准、控制、诊断修订、未知、交付和历史由什么受管状态承载；事务、引用、候选/最终、密钥、日志、备份、导出、删除和迁移的边界如何形成一套权威，而不进入普通 Session、FTS 或 Memory。
4. **任务与受管运行框架**：任务建档、四项职责、阶段与验收、四标签、自然日复盘、通知选择、主动投递、结果未知、主人控制、三态观测和迁移如何共享同一事实来源。
5. **模型、查询与非诊断问答**：怎样在发送前证明主人已同意的首跳路线，禁止主人派生查询路线外发送，控制 fallback，并为非诊断问答建立最小资料、结构化结果、诊断效果交接、安全优先和交付分层；当前 `ctx.llm` 不能证明有效容量、结构终态和实际 fallback 的缺口必须在本票选择具体补强接口路线，不能只写“实施时处理”。
6. **医学内容、诊断完整性与安全**：首发窄范围及来源许可路线如何选择；医学内容如何版本化、中文化、审核和退出；最小且完整资料、容量、结构终态、范围内外、危险升级、危险未明、安全能力不可用、处方药禁令、诊断修订和纠错怎样由不可绕过的健康路径强制。
7. **主人权利、删除、防复活与迁移**：查看、纠正、导出、停止记录、暂停支持、取消、撤权和永久删除怎样互不替代；完整副本清单、旧备份或旧 VM、防复活、源端停止和目标单一接管采用什么路线。
8. **权威文档与 Skill 组织**：哪些规则属于产品权威文档，哪些属于初始化或健康能力 Skill，哪些只能由 Plugin 代码强制；怎样保证搬迁时文档、Skill 与受管个人状态都能枚举和校验，且 LLM 会话记忆不成为权威。
9. **验证切面与实施依赖**：为每个关键边界选择可观察的验证点、故障注入位置、真实微信 canary、外部许可/医学审核门槛和实施依赖；本票只确定验证切面、证据层级与依赖关系，不展开完整测试矩阵，也不执行写生产、真实健康资料、外部许可接受、医学签字或破坏性实验。

完成时只形成一项统一 HOW Answer 和一份总 ADR：明确实际组件职责、稳定接口合同、每项权威对象及唯一写入者、事务与失败边界、C01—C17 的实现归属、被放弃候选及原因、外部硬前提、验证切面和后继实施依赖，并附旧 HOW 47—55 的逐项“继承、修订、放弃”对照表。50 中主人曾选择但未形成 Answer 的候选必须放回具体场景复核，不得让主人无解释地重答抽象问题，也不得静默升级为现行路线。不能只画模块图、列工具清单或复述 CAN；也不能在没有解释跨层状态与失败传播的情况下说“采用 Plugin + 数据库”。本票不展开数据库字段、消息 schema 细节、函数签名、医学阈值、部署命令、测试脚本或实现任务清单；这些属于后继 Spec、验证与实现工作。

如果选择过程中发现某个未知会实质决定是否存在可实施路线，本票必须暂停并新建精确 CAN 前提；如果暴露新的产品承诺或风险接受取舍，必须暂停并新建后继 TO。否则应在同一票内完成技术路线选择，不再拆回原来三张互相等待的 HOW。

## Answer

2026-08-20，选择[用一个 Plugin 私有 Health Core 统一入口、状态、模型、安全与运行](../../../docs/adr/0021-use-one-plugin-owned-health-core-and-governed-authority-stack.md)作为健康管家当前唯一技术路线。该 ADR 逐项固定 C01—C17 的实现归属、稳定 interface、唯一写入者、事务与失败边界、旧路线继承/修订/放弃、验证切面和后继硬依赖；本票只摘要主人旅程和关键取舍，详细技术权威以该 ADR 为准。

### 选定的端到端路线

- **仍是一个 Partner Hermes 和一个健康 Plugin 产品。** 主人只面对原 Hermes。Plugin 注册唯一自定义 `health_weixin` Platform Adapter；内置 `weixin`、Telegram 和其他人类健康入口禁用且不持有可回退凭据。Plugin 未加载时不会落回内置微信或普通 Agent。
- **增加一个 Plugin 私有、本机、低权限的 `health-core`。** 它没有人格、渠道、模型供应商配置、主人入口或自主定时动作，不是第二个 Agent、第二个画像或独立 LLM Gateway。它只通过权限受限的本机 socket 服务同一健康 Plugin，并作为 SQLite、密钥、规则、任务、诊断、outbox 和迁移状态的唯一写入者；Gateway 停止后它不能产生健康效果。这一选择明确修订旧“必须全部纯进程内”的路线，因为完整 CAN 已证明普通 Gateway 进程缺少健康密钥和状态隔离。
- **一份本地内容权威加一个无正文域外 current head。** 本地受管 SQLite 以标准认证加密统一保存 receipt/cursor、六域画像、三类证据卡、任务、批准、控制、诊断修订、未知、交付与历史，不再使用旧 sidecar 的多库、多文件、明文投影或自制密码学。单区域 DynamoDB 强一致 item 只保存不透明 generation/digest、transition id、writer fence 和终止标志；所有权威变化按“本地 prepare → 远端条件推进 → 本地 finalize”提交。它不是第二份画像，而是决定哪一个本地 revision 有资格成为当前。
- **一个深的 HealthCoordinator interface。** 入站、主人操作、调度唤醒、四项职责和模型候选都只能提交命令或候选；`health-core` 才能提交最终业务状态。业务结果与加密 outbox 同一 revision 提交，模型和微信调用在事务外执行。结果形成、业务提交、发送尝试、接口接受/拒绝/未知、主人实际到达严格分层。
- **不用当前原样 `ctx.llm`。** 为锁定 Hermes 增加一个很窄的 `StrictHealthLLM` host interface，仍读取同一 Partner 的实际模型配置和凭据，只能发到主人已同意的首跳，禁止跨首跳 fallback，不建立第二套 provider 配置。它从最终 wire payload 做容量证明，显式发送输出上限与严格结构格式，并原样保留 `completed / incomplete / failed`、不完整原因、实际 model 和 fallback 事实；不能证明容量或完整终态就不形成结果。
- **运行时不做主人派生的路线外查询。** 模型为 no-tools；健康路径不调用 Web Search、MCP、普通 Tool 或任意 HTTP。医学与一般知识由无主人数据的离线 `KnowledgePublisher` 按固定治理计划产生不可变本地 release，缓存缺失只形成知识缺口，不按主人问题临时回源。
- **首发诊断范围目标选择 BMI 窄范围。** 具体目标为“中国 18 岁及以上成人、非妊娠、近期身高体重测量可靠，仅基于 BMI 的超重、肥胖及肥胖程度 AI 辅助分类”。不拼入 NICE 或高血压规则。模型只产不可发送的结构候选；本地三段失败关闭、BMI 独立重算、五类安全结果、修订链和审核模板拥有最终放行权。当前尚未取得内容生产使用权、医学审核和范围验收，因此该范围仍是 staged，不得显示 active。
- **任务、复盘、控制和状态共享同一事实来源。** 原生 Cron 只唤醒；当地自然日账本决定是否已复盘。任务只用四标签，外部结果未知作为独立事实冻结重试。五类普通通知独立选择，关键安全/纠错/状态/行动请求不被普通偏好吞掉。暂停支持、停止记录、取消任务、撤回批准和永久删除是五种独立命令，不互相替代。三态由全部业务域聚合，进程或 Cron 活着不能冒充“活跃”。
- **删除和迁移使用同一个 writer fence。** 永久删除先冻结健康效果并把 DynamoDB 推进到不可恢复 terminal generation，再销毁密钥和清除 SQLite、索引、任务、outbox、备份、导出和迁移暂存；远端结果未知时不声称旧 VM 防复活已经完成。计划迁移先冻结源端并校验完整 manifest，再由一次 CAS 把 writer fence 交给目标；结果未知时两端都不写不发，旧源或旧 VM 永远不能凭本地副本恢复为当前。

### 场景对齐

| 场景 | 权威路径与主人结果 |
|---|---|
| 尚未初始化时说“我胸痛” | `health_weixin` 只把非初始化消息交给基础 Hermes；健康 Plugin 不识别、不记录、不安全分流，也不在以后倒填。只有确定性初始化入口可进入 pending 流程。 |
| 完成初始化 | `health-init` 说明披露和同意；时区、偏好、初始画像、密钥、本地 revision 与远端 current head 全部完成后一次启用。任何中断或提交未知都显示未启用。 |
| 说“夜班让我只睡四小时” | 原始 envelope 只在加密短生命周期区处理；长期 receipt 仅保存来源、时间、字段存在性、带密钥摘要和处理状态，不保存正文或媒体。主人陈述经证据维护准入后才进入最小证据卡，并只在睡眠等现有六域主题中更新简短当前理解；达到任务硬门槛才建任务，普通 Session 不保存健康正文。 |
| 同一消息再次到达 | 两次来源都保留；无法证明重投还是主人再次发送时不产生第二次画像、任务或诊断效果。只有影响判断时问一次，危险检查不等待。 |
| 当日复盘或停机恢复 | Hermes 定时器只发 wake-up；core 以当前时区和当地自然日账本判断。无变化安静，有变化同事务提交任务/画像变化和 outbox；恢复只处理当前日，不补过去积压。 |
| BMI 资料缺失或范围内结果成立 | 缺必要资料时主人看到“未形成辅助诊断”且不建诊断记录；全部门槛通过后才显示结构化判断、支持/反对证据、关键未知、紧急程度和下一步，长期只留结构化结果与最小引用，不留完整回复或模型草稿。 |
| 范围外、危险升级、危险未明或安全能力不可用 | 范围外仍先做安全分流，但不建诊断记录；危险升级停止诊断并给固定人工医疗/急救提示，只留最小危险事件与交付状态；危险未明只问最小问题或建议及时人工评估，只留最小缺口/处置；安全能力不可用只给非个性化最低求助提示，并只留无健康正文状态。 |
| 医学来源失效或主人纠正事实 | core 先让依赖该依据的旧判断退出当前，再显示修订、降级、撤回或替代及原因；若旧判断曾影响主人，产生一次必要纠错通知。旧判断留在修订链中但不再冒充当前。 |
| 首跳变化、容量或模型终态无法证明 | 所有需要该新路线的健康处理停止，不切 provider、不删必要资料、不发送部分结果；不需要新接收方的查看、纠正、导出和删除仍可走本地权利路径。 |
| 模型或微信调用结果未知 | 未越过业务提交就没有最终结果；已提交但微信未知时业务结果仍成立，只把交付标 unknown；可能已产生外部效果时冻结自动重试，不把 unknown 改成 failed。 |
| 暂停支持、停止记录、撤权或删除 | core 分别应用独立控制。暂停不取消任务；停止记录仍可临时回答和危险处置，但不长期新增证据、画像、诊断、安全事件或任务，恢复后不倒填；撤权阻止未发动作并保留在途未知；删除进入 terminal generation 并覆盖全部受管副本。 |
| 旧 VM 恢复或搬到新 Hermes | 旧 VM 的 generation/digest/fence 与 DynamoDB current head 不符，所有健康写入和发送失败。迁移只在目标持有新 fence 后启动，源端立即失去权威；文档、Skills、知识包、状态、密钥引用和全部任务/控制一起迁移。 |

### 权威文档、Skill 与实现边界

运行 release 必须枚举当前产品合同 bundle、本 ADR、画像 schema、任务/控制/状态合同、`health-init`、`health-steward` 和四职责 Skills、医学/安全/模板 bundle；锁定的 Hermes artifact/patch、`StrictHealthLLM`、Plugin/core、`health_weixin` 配置与唯一 allowlist 引用；Gateway/core/observer/KnowledgePublisher 的 service unit、运行用户、sandbox/ACL、依赖锁、发布计划与运行配置；受管 SQLite、密钥/credential 引用、DynamoDB current-head/observation resource identity。秘密只在目标重新配置并验证，不进入 manifest。Skills 提供可发现说明和只读职责流程，Plugin/core 代码强制准入、权限、事务、安全和失败关闭；LLM 会话记忆永远不是权威。
