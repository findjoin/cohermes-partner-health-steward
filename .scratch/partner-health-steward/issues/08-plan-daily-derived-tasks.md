# 08 — 实现每日画像复核与派生任务规划

**What to build:** 让每日 04:00 的 fresh-session 日检基于当前画像、证据、任务反馈和资料卡自主选择不行动，或创建有依据、可撤销的即时或未来派生任务。

**Blocked by:** 04 — 实现画像状态、冲突、失效和交互偏好；05 — 建立受控医学资料库与按需核验；06 — 实现主人自查、查看授权与只读访问

**Status:** resolved

- [x] 日检按画像主人时区的 04:00 运行，所有持久时间以 UTC 记录，默认时区为 Asia/Shanghai。
- [x] 日检输入包含当前画像、有效证据、相关资料卡、任务反馈和暂停/授权状态，不依赖旧聊天 session。
- [x] 日检能够明确产生 `no_action`，不会为了自治而强制创建任务。
- [x] 可创建的任务仅包括画像补全问题、状态追问、关心消息、授权低风险提醒、即时对话或未来触达。
- [x] 每个任务保存目的、证据引用、时间窗、有效期、去重键和策略约束，不保存最终旧文案。
- [x] 待核实假设最多生成一次补全问题；诊断、改药和外部第三方通知不成为任务。
- [x] 日检可以维护画像和资料卡并创建任务，但不能直接发送消息或创建新的原生 Cron。
- [x] 日检失败后 10 分钟只重试一次；再次失败时当天不产生新任务并记录失败。

## Answer

Ticket 08 已实现。日检通过 sidecar store、partner adapter 和 Unix-socket 协议提供快照与结构化任务规划入口；任务只保存目的、证据/资料引用、时间窗、有效期、去重键和策略约束。实现包含暂停与授权状态、资料扫描维护、画像生命周期刷新、同日幂等、同目的去重、假设补全问题一次性锁定、失败后 10 分钟单次重试，以及无内容失败审计。定向测试 9 项通过、Unix socket 在 Windows 跳过；完整测试 243 项通过、13 项跳过。
