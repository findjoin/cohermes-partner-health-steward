# 【CAN】核验微信 iLink 与目标 Hermes 的真实接口能力

Type: research
Status: resolved
Parent: [健康管家首发 TO、CAN 与 HOW 决策闭合路线](../map.md)
Blocked by: None

## Question

在不选择 HOW、不修改目标现场且不发送测试消息的前提下，腾讯微信 iLink 的官方接口与官方实现，以及目标 Hermes v0.20.0 的固定提交和当前目标现场，真实提供、缺失或未承诺哪些能力？研究至少覆盖：私聊、群聊和身份字段；入站消息封套及各字段的可选性；`message_id`、`seq`、协议时间与同步游标的物理含义和保证边界；重复投递、去重、快速连发合批及处理成功前后的确认语义；回复和主动发送的接口结果与主人真实到达边界；进程中断、重启、游标恢复和无法确认状态。

结论必须逐项区分五个证据层级：腾讯官方明确保证、目标固定提交源码行为、目标现场已只读验证、尚未验证、必须取得主人批准后才能通过真实主人微信实验验证。优先使用一手来源并给出固定版本或提交引用；既有 Evidence 07 只能作为待复核输入，不能替代本票的完整答案。若需要真实微信实验，只列出最小实验目的、动作、可能产生的数据或外部影响和停止条件，等待主人另行批准，不得自行执行。产出一份带引用的 Markdown 证据，并在本票 `## Answer` 中链接和概括；只给 CAN 事实与其对后续 HOW 的约束，不选择接入、存储、去重、发送或恢复实现。

## Answer

完整证据见[微信 iLink 与目标 Hermes 真实接口能力核验](../evidence/08-weixin-ilink-target-hermes-interface-capabilities-20260816.md)。

腾讯 iLink 的固定官方接口与目标 Hermes v0.20.0 提供单个微信身份的私聊收取、回复以及复用 `sendmessage` 的主动发送技术入口，但公开契约不保证消息封套字段完整、重投时标识稳定、逐消息确认、游标恢复、恰好一次处理或主人微信真实展示和收取。目标内置微信路径又会先持久化批次游标再异步处理，并在主人准入和业务成功前执行 300 秒内存去重及快速文本合批；发送结果最多证明接口未报告错误，本地 `client_id` 不是微信送达回执。

目标现场已只读确认运行于固定 Hermes v0.20.0 提交，微信 Adapter 与该提交一致，当前准入收敛为单值私聊 allowlist；但现场没有健康 Plugin、健康定时任务或本次真实微信端到端验证。其余未知事实及必须经主人另行批准的最小真实实验已在证据中逐项列明，均未执行。

这些结果约束后续 HOW：必须在现有正文去重与合批之前保留每条可用来源证据；把游标推进、业务完成、接口接受、结果无法确认和主人确认看到分开；不得把缺失字段、本地标识或接口无报错冒充可靠来源、恰好一次或真实送达。Hermes 仍有正式 Plugin/Adapter 扩展空间，当前未证明 TO 不可实现，因此本票不创建 TO-CAN 差距决策，也不选择 HOW。
