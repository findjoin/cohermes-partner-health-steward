## Question

在已经确认“旧状态恢复不得复活已失效身份、已使用或撤销的恢复权利及不可恢复锁定”，并已选择同一健康 Plugin、专用 SQLite 和专用加密备份数据平面的前提下，目标 Partner Hermes 运行环境及其真实可用依赖，究竟提供、限制或缺失哪些可把当前身份授权代际保持在健康数据回滚域之外的受支持能力？只核验 CAN，不选择状态锚点、服务、供应商、凭据、协议或最终 HOW。

研究至少覆盖：Hermes full backup、quick snapshot、Plugin 数据备份、整机磁盘或虚拟机快照及人工恢复分别会回滚哪些状态；目标主机、虚拟化层、托管平台和可用外部服务是否真实提供单调代际、条件更新、不可覆盖记录或其他能够拒绝旧状态的权威事实；这些机制面对管理员、操作者、服务器所有者、备份恢复、进程重启、网络分区和自身故障时的保证边界；读取、推进和原子提交语义，认证与凭据启动问题，可用性和故障域，最小无健康正文状态，永久删除后的保留边界，以及目标现场当前已安装、已配置、可调用和未证明的事实。

必须分别记录官方保证、固定版本或接口行为、目标现场只读事实、推论、未知项和需要主人另行批准的最小实验。不得创建云资源、开通服务、修改配置、写入状态锚点、恢复备份、制造故障、读取健康正文、身份值或凭据，也不得发送微信或模型请求；需要外部账户、付费资源、写入或破坏性实验时，只列明目的、外部影响和停止条件并等待批准。

产出带固定引用的 Markdown 证据并追加 `## Answer`。若没有已证实可承载既定承诺的能力，形成负向 CAN，并保持健康管家初始化、产品级验收和正式上线为 No-Go；不得静默降低已经确认的 TO，也不得提前生成身份迁移与恢复 HOW。

## Answer

完整证据见[抵抗旧状态恢复的身份权威锚点能力核验（2026-08-18）](../evidence/17-owner-identity-authority-anchor-capabilities-20260818.md)。

结论是**负向 CAN**：截至 2026-08-18，目标 Partner Hermes、当前 DMIT/KVM 来宾、已选择的健康 Plugin 专用 SQLite/加密备份数据平面和目标现场已安装依赖中，没有一项已经配置、接通并得到端到端证明的身份权威能力，可以在旧状态恢复后仍拒绝已经失效的身份、已经使用/替换/撤销的恢复权利及不可恢复锁定之前的状态。

必须区分不同回滚域：Hermes full restore 只覆盖归档内成员，可能让包内身份状态回旧而域外 Plugin DB 保持较新；quick snapshot 不含任意 Plugin 数据，也可能回滚 Hermes 核心而留下较新 Plugin 状态。两者会制造代际不一致。Plugin 专用加密备份与整机/VM snapshot 则可恢复一个内部一致但已经过期的本地状态集合；SQLite 事务、AEAD、`fsync` 和加密只能证明提交/内容完整性，不能证明恢复后的状态是最新代际。

现场只读核验确认：来宾为单一 ext4 根盘上的 KVM/QEMU Q35 虚拟机，没有 `/dev/tpm*`、EFI variables 或第二个独立持久盘；QEMU Guest Agent 与 watchdog 在运行，但它们不是域外权威。DMIT 官方只公开 point-in-time snapshot/rollback 与可选异机备份，没有公开应用级单调代际、CAS、不可覆盖身份记录或恢复后拒绝旧状态的合同；来宾也不能证明当前账号是否启用了这些 add-on。

目标 venv 已安装 `boto3`/`botocore`、`httpx` 和 `requests`，只证明存在一般客户端构件。现场没有已证明的外部账号、资源、credential 接线或可调用锚点；常见云/备份/一致性服务 CLI、配置目录与本地服务也未发现。公开一手合同证明现实中存在强一致读、条件更新和 WORM 等外部原语，但不能把公开服务能力冒充本项目已经选择或可用的依赖。

若保持既定 TO，未来候选能力至少必须位于全部来宾恢复域之外，提供强一致当前代际、基于预期代际的线性化条件推进、不可倒退约束、唯一转换标识与不含健康正文的状态摘要，并把超时/网络分区/credential 或远端故障表达为“结果未知”并失败关闭。SQLite 与域外权威没有现成共同事务，跨域提交窗口及永久删除后最小防复活事实的保留也必须由候选路线另行证明。

本票没有选择锚点、服务、供应商、凭据、协议或 HOW，也没有读取 secret/身份/健康正文、写入状态、恢复备份、创建资源、制造故障或发送模型/微信请求。健康管家可以安装 Plugin，但初始化、创建正式健康画像、保存健康资料、产品级验收和正式上线继续 No-Go；不得直接生成身份迁移与恢复 HOW。若主人以后批准引入某个域外候选，必须先用新的候选专属 CAN/Prototype 核验真实账号、资源、权限、强一致/CAS、可用性、保留/删除和故障语义，再决定是否具备进入 HOW 的事实基础。
