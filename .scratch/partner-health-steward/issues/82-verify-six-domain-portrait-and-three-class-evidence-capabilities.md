# 【CAN】核验紧凑六域健康画像与三类证据卡的维护追溯能力

Type: research
Status: resolved
Parent: [健康管家首发 TO、CAN 与 HOW 决策闭合路线](../map.md)
Blocked by: [【CAN】核验受管健康状态数据平面、保护隔离与单一权威能力](81-verify-managed-health-state-plane-protection-and-single-authority.md)

## Question

在已证明可承载受管健康状态的候选能力中，能否稳定表达并核验[【TO】确定健康任务的自动生成、派发与生命周期合同](73-define-health-task-generation-dispatch-and-lifecycle-contract.md)现行 Answer 固定的顶部“当前状态”和以下完整导航，而不回退到旧七域：

1. 临床与安全事实：症状与健康问题；主人转述的医生结论与既往问题；用药；过敏、不耐受与危险警示；检查、化验和生命体征；相关时的免疫、手术/操作、医疗设备、家族史和生殖健康。
2. 身体功能与主观身体体验：疼痛；疲劳与精力；睡眠；感觉；心肺；消化代谢；泌尿生殖；运动及其他身体功能；对生活的影响。
3. 心理、认知与主观福祉：情绪；焦虑与压力；积极情绪与生活满意度；应对；注意、记忆、学习与决策；心理痛苦；功能受损；自伤风险。
4. 活动与社会参与：沟通与学习；移动；自理；家务；学习或工作；关系；社会角色与社区参与。
5. 健康行为与相关暴露：身体活动；饮食模式；睡眠作息；烟草或尼古丁；酒精及其他物质；其他相关暴露。
6. 主人目标、价值与健康/照护偏好：期望的健康或功能结果；优先级；时间范围；可接受负担或权衡；健康与照护偏好。

每个固定二级主题只保存简短当前理解或明确未知、趋势、开放判断、关键未知、关联任务和证据索引；相关生活因素只做最小跨主题链接。“新增、改名、合并或删除二级主题前先取得主人同意”必须可核验。空白、冲突、过期或无法证明当前适用的内容保持未知，不得被模型文字补成正常或事实。

同一能力是否能把个人健康证据、通用权威知识和任务过程证据严格分为三个不可自动互换的一级类型，并在每类六域索引下维护唯一最小证据卡及来源、事件/记录时间、版本、准入、用途、不确定性、支持/反对、纠正、撤回和失效关系；画像主题和任务只链接同一权威卡，不复制证据正文？主人回答、搜索命中、任务 `solved`、提醒送达和关心完成都必须停在其真实证明范围，不能直接改写个人事实、诊断或健康改善。

本票只调查结构化状态、引用和职责接口能否支持这些语义，不选择文件格式、字段名、数据库或四个 Skill 的实现。模型生成一段看似正确的画像文本不构成证据；结论须以可复现的状态前后差异、冲突/撤回样例、引用唯一性和主人批准门禁为边界。

## Answer

完整调查、事实分层与可复现边界见[《紧凑六域健康画像与三类证据卡维护追溯能力核验》](../evidence/23-six-domain-portrait-and-three-class-evidence-capabilities-20260820.md)。本轮只读取现行产品合同、固定 Hermes 源码、同日正式 Partner 的前置脱敏事实和当前工作树候选，并用临时目录运行非真实健康的既有定向测试；没有读取正式环境的聊天、健康正文、凭据、数据库、备份或日志内容，没有连接或修改正式 Partner，也没有调用模型、发送消息、安装依赖或执行故障与恢复实验。

当前正式 Partner 没有已部署的健康 Plugin、受管健康状态或可验收的画像与证据对象，所以顶部“当前状态”、六个固定一级领域及全部固定基础二级主题、主题的明确未知、三类证据卡、唯一引用和二级主题主人批准门禁均**未实现且未证明**。固定 Hermes 只提供通用 Python Plugin 与结构化 Tool 承载面；它没有现成的健康对象模型、受管 Plugin 状态、跨对象引用或职责写权限合同，只能证明未来实现仍有接入空间。

未部署的旧 sidecar 候选有局部可复用原语：个人陈述、测量和主人转述医生内容可以分型准入；一次修改能形成个人证据、不可变画像版本并切换当前版本；高影响冲突会降为待核实，过期结论退出当前摘要；通用资料卡保留版本和失效边界，并且不会沿现有查询接口直接生成个人事实或任务动作。十项既有定向测试在本地临时状态中全部通过，但只证明这些旧候选局部函数，不能冒充 C05 或生产验收。

该候选的完整对象合同与现行 TO 不兼容：画像仍是 `state / habit_goal / interaction_preference / task_context` 四类平面结论和一段摘要，没有六域固定拓扑、各主题明确未知或主题结构变更批准；`direct_statement / measurement / owner_relayed_clinician` 只是个人证据内部的来源子型，通用资料另存于 source library，任务过程散落于 task/audit，三者没有统一的三类证据卡或一致六域索引。个人证据、资料卡、画像版本和任务虽有局部 ID，但画像结论没有稳定对象 ID，资料卡引用接受未校验字符串；用途、不确定性、支持/反对/限定、纠正、撤回、失效和后继关系也没有在同一证据卡合同中闭合。主人询问、文献查找、证据维护和画像维护的写权限同样未形成可核验的职责接口。

因此本票给出一项**负向但已闭合的 CAN 事实**：底层通用原语部分可用，当前正式能力和当前仓库候选均不能稳定表达并核验现行六域画像与三类证据合同。该结论不降低任何 TO，也不选择文件格式、字段、数据库、索引介质、四个 Skill、Plugin/sidecar 组织或其他 HOW。以后比较候选路线时，必须用六域与固定主题可定位、空白明确未知、主题变更先获主人同意、三类不可互换、冲突/纠正/撤回传播、同一权威卡引用完整以及可复现状态前后差异来验收，不能用模型生成文本或局部字段存在冒充成功。
