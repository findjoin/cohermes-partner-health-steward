# 09 — 实现到期快照渲染与消息派发

**What to build:** 让每 5 分钟运行的派发流程在任务到期时读取当前受控健康快照，再为每个任务建立独立的 fresh LLM session，决定发送或跳过；不得发送创建任务时的旧文案。

**Blocked by:** 05 — 受控医学资料库；06 — 主人自查、查看授权与只读访问；08 — 每日画像复核与派生任务规划。

**Status:** resolved

- [x] 按五分钟轮询粒度选择到期任务；每个任务通过 `complete_fresh(..., session_id)` 建立独立 LLM session，不复用旧聊天 session。
- [x] 快照包含任务目的、时间窗、证据 ID、当前 300 字画像、相关结论、授权交互偏好与同一主人最近三条消息。
- [x] 快照是当前健康状态的唯一依据；Hermes 其它上下文只影响表达方式，不得覆盖 sidecar 状态。
- [x] 渲染前和发送前均重新核对授权、暂停、结论有效期、资料卡新鲜度、任务去重、时间窗、任务状态与 claim；失效前提只会产生 skip。
- [x] 渲染输出严格限制为 `send` 或 `skip`；不修改画像、资料卡、任务计划或 Cron。
- [x] `send` 通过受控渠道适配器发送当前文案；`skip` 保留模型理由供下一次日检重新判断。
- [x] LLM 或可确认失败的幂等渠道调用在 15 分钟后最多重试一次；不支持幂等的渠道发生不确定异常时立即终止，避免盲目重复投递。
- [x] 任务 claim、稳定 delivery key、状态结果和无内容审计字段（角色、动作、对象、结果、理由、证据 ID）可查询。

## Answer

Ticket 09 已实现。派发器通过 sidecar store、partner adapter 和 Unix-socket 协议提供到期任务渲染入口，使用 `complete_fresh(..., session_id)` 为每个任务建立独立 LLM session，并在受控渠道交付前再次取得状态锁核对授权和任务前提。任务状态包含 claim、重试和稳定 delivery key；渠道适配器必须提供 `send_once` 幂等端口，不确定的非幂等渠道会失败关闭。普通聊天可经独立的已验证临时消息入口进入最近三条快照，但不会写入证据或画像。模型 skip 理由保留在任务状态并返回给日检，审计只保留无内容元数据。

验证：Ticket 09 定向测试运行 11 项，其中 10 项通过、Windows 上 Unix-socket 1 项跳过；完整 `partner-health-steward` 测试 **257 项通过、14 项跳过**。AF_UNIX、受限账户和真实 Hermes Job 的部署验收仍需在 Linux 非生产环境完成；本次未部署生产服务。
