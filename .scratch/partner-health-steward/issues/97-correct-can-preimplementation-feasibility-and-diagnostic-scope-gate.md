## Question

当前 Map 已规定完整 CAN 闭合前不得进入 HOW、实现、验收或上线，CAN 只调查真实能力、约束和未知；但现行能力链与闭合票又把“正式 Partner 已经存在一个已激活诊断范围”设成 CAN 闭合前提。由于已激活诊断范围必须经过尚未开始的 HOW、实现、医学专业审核、范围产品验收和真实主人验收，这两组规则形成“尚未实现 → 零已激活范围 → CAN 不能闭合 → HOW 与实现不能开始”的循环。

在不改变任何 TO 产品目标、不选择 HOW 路线、不把未知冒充可行的前提下，怎样修正当前 CAN 阶段合同和依赖图，使 CAN 把 TO 的最终产品结果转换成可实施性事实、现实约束、外部前提与未来验证义务，而不是要求尚未实现的健康管家已经工作？同时应怎样区分“当前尚未实现、部署、激活或验收”与“某条候选支持路线已经被证据证明不可行”，并修正病种候选调查和三轮负向研究计数，避免用同一共同缺口反复生成新票？

完成条件是：

1. 在 Map Notes 增加明确的 CAN 防循环规则，并保持 `TO → CAN → HOW → 实现与产品级验收` 的职责边界。
2. 明确内容使用权、中文来源版本、医学专业审核和范围产品验收在 CAN 中分别需要证明到什么程度，哪些属于 HOW、实现或上线前依赖；不得把尚未执行等同于已经不可行或已经满足。
3. 明确负向 CAN 与研究轮次只针对实质不同的候选能力或支持路线；换病种但重复“产品未实现、未部署、未审核或未验收”不计新一轮。
4. 保留既有 CAN 报告中的 Hermes、旧候选代码、医学来源、权利与风险事实，但由本后继票明确取代“零已激活范围不得闭合 CAN”及由此产生的轮次结论；不得改写历史 Answer 冒充原决定。
5. 停止当前第三个病种候选调查，重接 CAN 闭合票，使其下一轮只判断现有能力事实、限制和未知是否已经足以进入 HOW；若仍有会改变 HOW 可行性的真实未知，再由闭合审计准确出票。
6. 本票追加恰好一个 `## Answer`、改为 `resolved`，并在 Map 的 `Decisions so far` 增加一条摘要；完成后依赖图无缺失、无环，Map 仍只有五个顶层部分且只有 CAN 闭合票成为唯一 Frontier。

本票只修正阶段语义、权威关系和调查图，不实现健康管家，不选择 Plugin、Skill、文档、存储、模型、医学来源组合或验证工具，也不降低“完整首发健康管家最终至少包含一个已激活诊断范围”的 TO。

## Answer

阶段循环已经修正，TO 产品目标保持不变。错误根因是把“产品实现后才可能成立的完整上线结果”提前当成了“实现前 CAN 必须已经成立的能力事实”：例如画像更新功能尚未编写时，调查只能说明当前没有该功能，并核验 Hermes 扩展面、受管状态和安全边界能否承载它；不能把不存在的成品当作测试对象，再用“测试未通过”证明路线不可行。

当前权威阶段关系是：

`TO 最终产品合同 → CAN 可实施性事实与约束 → HOW 技术路线选择 → 实现并取得外部前提 → 产品级验收与上线`

CAN 闭合不要求健康 Plugin 已部署、健康功能已运行或诊断范围已激活。它必须证明：现有平台与外部现实中至少存在一条由当前事实支撑、没有已知根本矛盾、足以交给 HOW 选择的可实施路线；同时列清硬约束、仍会改变路线可行性的未知、必须取得的外部前提和实现后的验证义务。如果一手证据证明没有可用扩展面、没有任何合法来源取得路线，或某个未知会决定 HOW 是否成立，这才继续阻塞 CAN。仅有“代码尚未写、尚未部署或尚未验收”不构成负向 CAN。

诊断相关门槛按阶段承担：

| 门槛 | CAN 必须核验 | HOW 必须选择 | 实现后必须完成 |
| --- | --- | --- | --- |
| 内容使用权与中文版本 | 许可条款、申请或取得入口、版本与更新限制、已知 No-Go、当前授权状态 | 具体来源、版本、许可取得和失效退出路线 | 取得并保存实际授权证据；未取得不得激活 |
| 医学专业审核 | 审核对象、资质要求、可获得入口和现实限制 | 审核职责、流程、输入工件及通过门禁 | 对实际内容、诊断规则和危险边界完成合格审核 |
| 范围与产品验收 | 范围是否可准确界定、结果是否可观察和测试、所需接口及失败边界 | 范围实现、分层验证和真实验收方法 | 对实际产品完成范围验收，并由真实主人通过真实微信验收 |

因此，找到许可申请页不等于已经获权，找到审核入口不等于实际规则已经通过审核，写出验收场景也不等于产品已经验收；反过来，这些后继动作尚未执行，也不能证明路线不可行。完整首发最终仍必须至少有一个范围取得所需权利、完成专业审核和产品验收并实际激活，这一 TO 没有降低。

- 当前 Partner/Hermes 基线、固定源码限制、未部署工作树的确定性反例、BMI 与高血压的医学来源差异、候选边界、权利限制、测量、安全和修订要求全部保留，作为 HOW 约束、外部前提或未来验证义务；它们不是已经运行的产品功能测试。
