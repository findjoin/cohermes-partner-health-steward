## Question

在当前 Partner Hermes 的 Plugin 生命周期、健康入口、唯一微信准入、受管状态底座和六域画像/三类证据语义已经取得当前事实后，固定 Hermes 的 Plugin 状态、内部 dispatch、Cron/时区、Skill/Tool/Command、消息发送、业务自检、服务观测、备份/导出/恢复表面，以及当前工作树候选，能否共同支撑一套以同一受管权威状态为中心的健康任务与运行框架，使任务推进、当地自然日复盘、主人控制、外部结果未知、三态状态和整套产品迁移成为可追溯且互相一致的状态变化，而不是彼此独立、可以互相绕过的工具？

本票一次核验以下五组不可拆开的能力边界：

1. **健康任务生命周期与四项职责（C06）**：只有当前可追溯依据、明确健康目的、承担者、触发条件或时限、允许资料和可判定结果全部成立才建立任务；一项可独立验收结果对应一项任务，询问、查找、证据准入和画像更新通常只是阶段。画像维护、证据维护、主人询问、文献查找和 Plugin 任务框架的输入、写权限、目标、验收与终态权威必须分离。主人默认看到关联画像主题、一句话目的、所需信息/支持/行动结果、当前进展与下一步、验收、四标签和自己现在需要做什么，并可展开建立依据、允许资料、承担者/接收方、外部效果、授权、阶段、通知、证据和前序/后继关系；主人能够查看、延期、调整或取消普通任务。任务须支持 `active/solved/failed/cancelled` 四标签，延期只是 `active` 的可见情况，等待、能力缺口和结果未知另作真实附加事实；`solved/failed/cancelled` 不静默重开，新证据、复发、新能力或主人重新提出只能形成有链接的后继任务。小步骤可以在范围内自适应，实质新目标、资料、承担者、接收方或外部效果须重新授权。任务只长期保留目的、标签与阶段、验收、批准或撤回、关闭原因、未知或交付等最小事实及已准入证据链接，不保存完整聊天、提示、草稿、内部推理、完整问答/诊断回复、非必要重复尝试明细或搜索结果堆；只有交付文字本身就是普通关心/提醒任务验收对象时，才保留一份完成验收所需的最小最终文字。普通待办 CRUD、Cron 触发、计划文本或一次 Tool 返回均不足。
2. **当地自然日复盘、通知、投递与恢复（C07）**：每个主人当地自然日业务级完成一次受影响画像和开放任务复盘，主人可查询最近结论，无有意义变化时安静，时区变化、错过、重启和恢复后只按当前状态重判且不补积压。新任务、普通阶段变化、关心/提醒、任务终态和复盘摘要五类普通通知可分别选择；危险升级、必要纠错、全局状态关键变化及一次必要行动请求不得被普通通知关闭。结果形成、发送尝试、接口接受和主人真实到达必须分层；超时、崩溃或在途结果不明时保持未知并禁止盲目重发。
3. **主人权利、分离控制、永久删除与防复活（C14）**：主人能够查看、纠正和导出同一画像当前快照，并沿索引访问相关证据、任务、阶段、批准、未知、交付和诊断修订关系；导出默认人可读、可提供机器可读形式、不含完整聊天，也不形成第二份继续变化的权威画像。画像更新须如实返回已更新、未更新、拒绝、失败或无法确认；行为设置只改变联系时间、表达方式和主动联系偏好，不能关闭安全规则。暂停主动支持只停普通主动询问、关心和提醒，不自动取消任务或撤回另行批准动作；停止新增记录仍可临时回答主人主动问题和执行危险处置，但不长期写入停止期间的新健康内容、不建相应新任务，恢复后不倒填；取消任务停止其后续阶段但不抹掉已发生或未知外部效果；撤回执行批准使未开始动作不得发出，已发或未知动作停止后续推进和重试并保留真实未知。永久删除覆盖产品仍持有或控制的全部当前与历史受管正文、索引、临时资料、缓存、日志、临时导出、任务、批准、未知、交付和备份，立即停止读取、推断、复盘、任务和联系，不等待站外未知结果，也不承诺删除主人已下载、微信、模型服务或其他站外主体持有的副本或倒转已发生动作；旧 Hermes、Plugin、备份或 VM 状态不得复活已删除内容、撤回批准或终态任务，删除后只能由主人主动空白初始化。不得新增含义模糊的全局关闭、倒计时、固定保留期、删除回执、失联清理或管理员代删承诺。
4. **三态业务观测与跨故障域传播（C15）**：主人能查询“活跃、异常、无法确认”、最近确认时间、受影响能力及当前可依赖结果。任务、画像、控制、消息入口、调度、模型路线、安全、非诊断问答和诊断范围各自返回的当前状态必须按现行规则确定传播：核心确认故障为异常，当前权威无法证明为无法确认，已隔离的单项提醒未知或可选文献失败不得无条件拖垮全局，最后一个已激活诊断范围失效必须影响全局。可信前提失效或无法证明时停止相应健康处理；转为非活跃和恢复活跃各主动尝试一次不含健康正文的通知，不发送周期性绿色心跳。Gateway、Ticker、Cron、systemd 或单组件自报存活不得冒充业务活跃。
5. **权威资产和受管个人状态迁移（C16）**：产品文档、Skill、Plugin 受管状态、六域画像、三类证据、任务、批准与撤回、控制、未知、交付、诊断修订和删除状态必须形成完整、可枚举且不依赖 LLM 记忆的迁移边界。搬迁后来源与时间、引用、当前权威、批准有效性、终态和未知结果不得改写，源端与目标端不能同时形成两份继续变化的当前真相；目标端唯一入口、初始化状态、首跳同意和保护边界仍须正确。缺项、版本不兼容、权限或密钥错误、切换失败或结果未知时必须失败关闭并进入真实三态，不能空白初始化、补发积压或复活旧状态。该能力不是聊天账号迁移、真人身份恢复或恢复码。

以上五组须用同一组代表性状态旅程交叉核验：任务建立与阶段推进、当地日边界复盘、一次结果未知、主人分别暂停/停止记录/取消/撤权、故障导致三态变化、源目标迁移以及删除后旧状态尝试恢复。每一步只承认真正证明的效果：接口接受不等于送达，送达不等于主人行动，关心不等于情绪改善，任务 `solved` 不等于健康改善，进程存活不等于健康管家活跃，文件复制不等于语义迁移，文件或数据库记录消失不等于永久删除和防复活。

本轮候选边界固定为目标 Hermes 的官方或固定源码、已有 Partner 脱敏现场事实、当前工作树候选及其现有非真实健康测试。解决条件是在一份带引用的证据报告中，分别对 C06、C07、C14、C15、C16 给出已证明能力、限制、反例、未知和仍需批准的实验，并证明没有因合并而遗漏任一原票验收边界。当前能力不存在或只能得到负向结论也可解决本票；真实微信发送、时间边界、故障注入、删除、旧状态恢复、密钥操作和源—目标迁移演练若会改变正式或外部状态，仍须另行批准，静态证据不得冒充实验已经完成。

本票不选择任务状态机、Cron、outbox、通知通道、数据库、密钥、墓碑、备份、监控系统、探针、包格式、传输、锁、切换命令、Skill 数量、Plugin/sidecar 组织或其他 HOW，也不重新核验模型回答、医学内容或诊断判断本身是否正确。

## Answer

完整调查、事实分层、同一代表性状态旅程与被吸收票覆盖核对见[《健康任务与受管运行框架完整状态旅程能力核验》](../evidence/26-health-task-managed-runtime-state-journey-capabilities-20260820.md)。本轮只读取固定 Hermes 源码、既有脱敏现场证据和当前未部署工作树候选，并在本地临时状态中运行非真实健康测试；没有读取正式聊天、健康正文或凭据，没有连接或修改正式 Partner，没有调用模型、发送微信，也没有执行删除、旧状态恢复、时间边界、故障注入或双环境迁移。

当前正式 Partner 没有健康 Plugin、健康 profile manifest 或业务 Cron，因此 C06、C07、C14、C15、C16 均**未在 LIVE 形成**。固定 Hermes 只提供 Plugin、Cron、消息发送和一般进程/文件承载面；这些组件原语不能自行建立健康任务、业务复盘、主人分离控制、三态产品状态或完整语义迁移。

当前未部署工作树有可复用的局部原语：旧任务目的与证据校验、当地日去重和短窗口重试、接口 `accepted/rejected/uncertain` 账本及未知防重、查看与导出、暂停和停止记录、局部密钥删除、组件监控、发布哈希及主状态 blob 恢复。但完整状态旅程给出四个确定性反例：

1. 暂停主动支持和停止新增记录都会把所有未终结任务直接改成 `cancelled`，没有保持控制彼此独立；
2. 删除流程额外引入 10 分钟确认窗、固定备份清理期和永久删除终态通知，且未证明全部受控副本与完整旧状态不会复活；
3. 生产验收已经 `blocked` 时，组件监控仍可报告 `service_health=healthy`，也没有把画像、任务、控制、入口、模型、安全、问答及诊断范围统一传播为主人可查询的“活跃、异常、无法确认”；
4. 恢复只替换主加密状态 blob，发布清单也不包含全部权威文档、Skill、任务、证据、批准、未知、删除状态和投递对象，不能证明源端与目标端只有一份继续变化的当前真相。

C06 另有明确结构缺口：旧候选采用封闭任务类型和 `candidate/scheduled/due_for_render/sent/skipped/failed/cancelled` 状态，没有现行四标签、验收、承担者、阶段、批准/撤回、前后继关系、四项职责写权限或主人对单项任务的延期、调整与取消。外部效果未知虽会在投递账本中冻结重发，却随后被任务层错误写成 `failed`，不是 `active + 结果未知`。

C07 只能证明狭窄 04:00 窗口内的当地日期去重、无变化时不建任务、一次 +10 分钟重试和接口未知防重；未证明主人时区变更、长时间错过后按当前状态重判、最近复盘结论、五类普通通知选择、不可关闭关键通知、最终结果形成与主人真实到达的分层。C14、C15、C16 同样只有局部数据、监控和发布原语，不能满足完整主人权利与防复活、业务三态传播和权威资产迁移。

主报告运行 158 项候选定向测试，其中 151 通过、7 跳过、0 失败；主线程另以相邻但不同的九模块集合运行 157 项，其中 150 通过、7 跳过、0 失败。两组不能相加，且只证明旧候选按旧合同稳定运行；其中部分测试正是在固定上述冲突行为，不能冒充现行产品能力或正式验收。

因此本票形成一项**负向但完整的 CAN 结论**：现有 Hermes 与工作树候选尚不能支撑统一受管健康任务与运行框架。该结论不降低任何 TO，也不选择任务状态机、Cron、outbox、存储、密钥、墓碑、监控、迁移包、Skill 数量、Plugin/sidecar 组织或其他 HOW；真实微信、故障、删除、旧状态恢复和迁移演练仍须在未来候选明确且主人另行批准后执行。
