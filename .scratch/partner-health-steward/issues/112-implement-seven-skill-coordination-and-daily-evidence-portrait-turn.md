# 112 - 实现七 Skill 协调与日常证据画像处理

**What to build:** 初始化成功后，让健康、混合或无法确定的消息经过一次粗分流进入 `health-steward`，由它按目的取得最小上下文并协调七个 Skill。一次普通健康 turn 应能产生受管证据候选、画像修订或明确缺口，经过 core 的唯一权威提交后返回一份主人回复和真实 Skill 使用披露。

**Blocked by:** 111 - 实现唯一准入与主人初始化

- [x] `health-steward` 是唯一健康协调者；`health-settings` 处理主人控制意图；四个 B 类 Skill 只返回目的限定候选、缺口或无合格资料。
- [x] 每个 Skill 只取得当前目的所需的最小只读上下文；缺项时停止并返回缺口，不补猜、不截断后继续、不扩大读取。
- [x] Plugin/core 证明必需 Skill 的实际动作、版本和因果关系后才记录最小使用事实并追加系统披露；未使用 Skill 不显示。
- [x] `health-evidence` 的个人证据、通用知识和任务过程证据不可互换；每张权威卡只承载一个可独立判断主张，画像和任务只引用同一张卡。
- [x] `health-portrait` 只能基于已提交证据形成六域当前视图；六域显示预算、三类证据、四类关系、近期明细、受保护例外和滚动摘要遵循 `CONTEXT.md` 与最新 TO。
- [x] core 原子提交证据/画像业务事实和回复意图，Plugin 适配唯一主人回复；Skill、模型草稿和候选不得直接写库、发送或完成任务。

## Answer

已在当前本地 Plugin/core 合成验证边界内完成 Ticket 112。初始化启用后，保守粗分流把健康、混合和无法确定的消息统一交给 `health-steward`；设置、证据、画像、补问和资料查找职责只接收按当前目的裁剪的只读投影，并只返回类型化候选、缺口或无合格资料。

core 采用证据阶段与完整 turn 两段权威提交：个人健康、通用权威知识、任务过程三类证据具有不可互换的物理语义；每张卡只承载一个可独立判断的主张；画像固定为六域 45 个基础主题，并约束近期明细、受保护例外、滚动摘要、四类关系与显示预算。画像“当前理解”的结构化适用期必须与其证据卡 `applicable_period` 完全一致，不能从自由文本推断。

主人回复由已签名职责结果生成的原子组成。最终选择必须完整覆盖本次提交的证据 ID、画像主题 ID 和证据适用性变更 ID，且每个引用只能归属于对应职责结果；core 原子提交业务事实与回复意图，Plugin 只适配这一份回复并追加实际 Skill 使用披露。未使用 Skill 不显示，Skill/模型草稿和候选不能直接写库、发送或完成任务。

审查同时补强了重投和隐私闭环：相同原生消息 ID 只有在域分离、带健康密钥的 HMAC-SHA256 指纹一致时才共享一个业务 turn；每次投递仍保留自己的 cursor。冲突或旧 receipt 无法证明时清除正文并保持 cursor 不可释放；finalize 对 root 与已确认 alias 同事务提交；终态结果和健康状态必须经当前 head 强读；finalized prepare 回执只保留不可逆 command digest。

验证证据：Ticket 112 五个定向模块共 83 项通过，Ticket 111 准入/初始化回归 46 项通过；两路独立代码与事务隐私复审最终均为 0 个 P0/P1 阻塞。以上只证明本地合成 Plugin/core 合同，不代表真实 Hermes/模型/微信接口、部署或主人到达已经验收；这些仍由 Tickets 113—119 承接。下一张依赖票为 Ticket 113。
