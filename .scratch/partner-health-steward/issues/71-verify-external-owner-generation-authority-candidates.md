# 【CAN】核验域外身份代际权威候选的强一致与防回滚能力

Type: research
Status: resolved
Parent: [健康管家首发 TO、CAN 与 HOW 决策闭合路线](../map.md)
Blocked by: [【TO】确定旧状态恢复下的身份失效与健康管家启用边界](67-decide-owner-recovery-anti-rollback-launch-promise.md), [【CAN】核验抵抗旧状态恢复的身份权威锚点能力](68-verify-non-rollback-owner-identity-authority-anchor-capabilities.md), [【HOW】选择健康画像数据平面、模型调用与保护路线](49-choose-health-record-rights-and-protection-route.md)

## Question

在 Ticket 68 已证明目标 Partner Hermes、当前 KVM 来宾和本地数据平面没有已配置的防回滚身份权威，而 Ticket 67 又明确保留“旧状态不得复活失效身份、已消费或撤销恢复权利和不可恢复锁定”的产品承诺后，现实中哪些可从目标部署路线采用的域外能力候选，能够或不能够承载当前身份授权代际的权威事实？只核验 CAN，不选择供应商、账号、区域、资源、凭据、跨域提交协议或最终 HOW。

研究必须以一手合同和目标环境已证明事实为基础，至少比较：受管强一致键值或事务服务的当前读、条件更新与并发语义；带条件写或 WORM/保留能力的对象存储是否能同时定义唯一当前头；追加式或透明日志是否能可靠确定当前代际；不随来宾快照回滚的硬件单调计数器是否在当前托管边界内真实可得。对每个候选分别核验强一致读取、线性化 CAS、不可接受较小代际、幂等转换标识、超时与结果未知、网络分区、区域或服务故障、旧虚拟机携带旧应用凭据、应用管理员与外部账号管理员的覆盖或删除能力、账号/资源删除、费用与配额、数据地域、最小无健康正文状态及永久删除后防复活事实的保留边界。

必须区分四层：公开原语能表达什么；目标服务器当前客户端与网络是否具备接入前提；真实账号、资源、权限和合同是否已经存在；具体项目协议与 old-snapshot canary 是否已经验证。公开 SDK、产品页面或示例不得冒充项目已选用、已开通或已验证。若某候选只能防止诚实 Plugin 误信旧状态、不能抵抗恶意 root 替换代码或外部账号管理员改写权威，必须明确写出威胁边界，不得扩大既有 TO。

不得注册账号、购买或创建资源、读取或试探 credential、向候选服务写入记录、恢复备份、制造故障、发送模型或微信请求，也不得携带身份明文、恢复凭据、聊天或健康正文。需要账号内只读核验、付费资源、外部写入、网络分区或快照恢复实验时，只列明最小目的、外部影响、数据形态与停止条件并等待主人批准。

产出带固定引用的 Markdown 证据并追加唯一 `## Answer`。Answer 应给出事实型候选矩阵：哪些能力类别单独不充分，哪些候选在满足哪些尚未证明的前提后具有进入 HOW 比较的事实基础，以及每个候选仍需主人批准的最小 Prototype/现场核验；不得直接选定路线。若没有候选达到最低能力语义，形成负向 CAN 并继续保持初始化、健康资料写入、验收和上线 No-Go。

## Answer

完整证据见[域外身份代际权威候选能力核验（2026-08-18）](../evidence/18-external-owner-generation-authority-candidates-20260818.md)。

候选原语层 CAN 已闭合，但目标现场能力仍未闭合：公开一手合同证明两类能力具有进入后继 HOW 比较的事实基础，一是提供强一致当前读与线性化条件更新/可串行化事务的受管 KV 或事务服务，二是提供强一致单一 live object 并强制 ETag/generation 条件替换的对象存储 current-head 组合。它们只有在真实账号、Region/location、资源、最小权限 credential、费用/配额、resource identity、不可绕过的业务单调校验、持久 transition ID、结果未知回查、最小无健康正文状态和永久终止保留边界全部另行证明后，才能成为实际路线；公开 SDK、文档或目标 venv 中的客户端包不等于项目已选择、开通或可调用。

WORM/保留、对象版本历史、追加/透明日志、异机备份和裸硬件计数器单独都不充分。WORM 只保护指定版本，不能阻止新版本或 delete marker 成为当前；透明日志证明追加与包含，却不对同一画像执行 CAS 或拒绝冲突/过期追加；裸 TPM counter 不绑定授权摘要、转换和终止状态。当前 KVM 来宾又没有 TPM/vTPM，QEMU 模拟 TPM 可随 VM save/restore、migration 和 snapshot 保存，故硬件路线在当前托管边界没有进入 HOW 的现场基础。

这些外部原语能帮助遵循协议的诚实 Plugin 拒绝旧快照携带的旧前提，但不能单独抵抗恶意 guest root、仍持有通用写 credential 的任意代码或外部账号管理员改写 IAM、删除 resource/account。若主人要把这些主体纳入对抗威胁，必须先建立新的 TO；本票不扩大现有承诺。

同一 Map 现在可以建立身份迁移与恢复 HOW Ticket，只比较“受管事务/CAS”与“条件对象 current head”并决定项目协议，不得直接宣布可部署。HOW 选定候选、费用和地域边界后，仍需主人另批候选专属账号内只读核验、仅含随机 ID/整数代际/随机摘要的隔离 Prototype，以及可丢弃 VM/profile 的网络未知、并发、资源删除/重建和 old-snapshot canary。任何实验若将触及正式 Partner profile、真实 credential、主人身份、微信、模型或健康正文，必须停止。

截至这些现场证据和项目协议闭合前，健康管家仍只允许安装 Plugin；初始化、创建正式健康画像、保存健康资料、产品级验收和正式上线继续 No-Go。
