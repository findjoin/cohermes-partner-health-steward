# 03 — 从主人消息维护证据与紧凑画像

**What to build:** 让画像主人的健康消息在同一轮形成可追溯个人证据、不可变画像版本和不超过 300 字符的当前健康画像，而普通聊天与非主人消息不入档。

**Blocked by:** 02 — 建立 sidecar 最小纵向骨架

**Status:** resolved

- [x] 已登记画像主人发送的直接健康陈述能够形成带消息 ID、UTC 时间和必要原文片段的个人证据。
- [x] 测量记录保留类型、数值、单位和观察时间；本人转述的医生意见明确标记为本人转述。
- [x] 普通闲聊、非主人消息、资料卡内容和无来源模型推断不能成为个人证据。
- [x] 每次成功候选写入原子地产生新的不可变画像版本，并且当前画像指向最新有效版本。
- [x] `profile_summary_zh` 计算所有字符、不含 Markdown、最多 300 字符，并遵守 2/3/2/1 的结论类别上限。
- [x] 溢出时先清理失效项、合并同义项并延期低优先级无任务依赖项；仍溢出时以 `summary_overflow` 失败关闭，不进行硬截断。
- [x] 最新三条主人消息仅作为临时上下文，除被接纳的最多 300 字符证据片段外不复制完整聊天。

实现备注：画像绑定和消息暂存均要求受信入站网关签发的 receipt；sidecar CLI 只注入网关 Ed25519 公钥（`--receipt-public-key-path`），不持有签发私钥，也不复用加密主密钥。私钥留在 sidecar 外部的受信入站层，Hermes 只转交签名 token；真实部署连线属于部署验收，不在本票本地测试范围内。

## Answer

已实现并验证：结构化个人证据、测量与本人转述医生意见、不可变画像版本、300 字符无 Markdown 摘要、类别上限、急性状态 24 小时/习惯目标 30 天/交互偏好 60 天默认失效、过期/同义合并、低优先级延期保留、溢出失败关闭、消息暂存/失败重试/去重，以及通用状态接口隔离。入站 owner 绑定和消息暂存由外部受信入站层签发、sidecar 用公钥验证的 receipt 保护。

本机证据：定向 sidecar 测试 41 项通过、9 项因 Windows 无 AF_UNIX 跳过；全量测试 202 项通过、9 项跳过；编译检查和 staged diff 校验通过。Linux 受限账户、真实 Unix socket 和 Hermes 网关签发链路仍需部署验收，未在本票中冒充已完成。
