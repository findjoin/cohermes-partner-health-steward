# 04 — 实现画像状态、冲突、失效和交互偏好

**What to build:** 让当前健康画像能够随证据强度、时间、冲突和真实交互反馈自主演化，同时避免把猜测或偶发行为固化为事实与偏好。

**Blocked by:** 03 — 从主人消息维护证据与紧凑画像

**Status:** resolved

- [x] 画像结论明确区分事实、倾向和待核实假设，只有事实和倾向可供普通自动任务使用。
- [x] 待核实假设最多产生一次画像补全问题，不自动升级为个人事实。
- [x] 一般时效性陈述以较新的主人直接陈述更新，测量按时间并存，持久高影响冲突降级为待核实假设。
- [x] 无更短有效期时，急性状态 24 小时失效，习惯或目标 30 天失效，测量保留为历史观察。
- [x] 明确交互反馈立即生效；隐式偏好必须由 60 天内至少三次独立同方向主动行为支持。
- [x] 沉默、回复速度和一次性情绪不构成交互偏好证据；无新证据的偏好在 60 天后停止指导主动触达。
- [x] 所有状态变化生成新画像版本并保留证据引用，旧版本不可被就地改写。

## Answer

- `profile.py` 增加事实/倾向/待核实假设的任务资格字段；假设拒绝任务依赖，并限制一次补全问题。
- 普通陈述按 `source_utc` 新旧合并；测量作为历史观察并存；带相同高影响 `conflict_key` 的矛盾陈述生成待核实假设。
- “持久高影响冲突”采用可复核的重复确认规则：至少来自两个不同主人消息、且观察时间不同的矛盾证据才降级；生成的假设按最后证据和类别默认期限失效。
- 交互偏好支持显式立即生效，以及三条来自不同主人消息的独立同方向行为后激活的隐式偏好；沉默、回复速度和一次性情绪被拒绝，60 天无新证据后失效。
- 画像版本与证据引用仍通过 sidecar 原子追加保存，旧版本不改写。
- 验证：定向 sidecar 测试 46 项通过、9 项跳过；全套仓库测试 207 项通过、9 项跳过。Windows 因无 AF_UNIX 跳过 9 项，Linux 受限账户/真实部署仍待部署验收。
