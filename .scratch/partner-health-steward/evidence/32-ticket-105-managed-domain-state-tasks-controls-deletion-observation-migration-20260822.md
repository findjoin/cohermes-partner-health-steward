# Ticket 105 受管领域状态、任务时序、主人控制、删除、观测与迁移核验（2026-08-22）

## Answer

K06—K10 及通用 K18—K20 的固定原语和少量历史候选局部机制已证明或可有界继承，但当前 Partner 没有可定位的受管健康状态面；六域画像、三类证据卡、四标签任务、独立控制、完整删除防复活、业务三态和完整迁移均尚未实现或未证明。旧 sidecar、普通 Session/Memory/backup、进程存活和测试通过不能作为当前健康权威。

## 证据边界与分类

本 Evidence 只读取当前仓库、`CONTEXT.md`、Ticket 102—105 及其直接引用的历史 Evidence 和未部署 `ops/` 候选源码；没有读取或上传真实健康资料、聊天、联系人、运行数据库、日志、备份、密钥、Token 或服务器配置值，没有执行删除、恢复、故障注入、双环境迁移、真实发送、部署或验收。2026-08-20 的现场只作为带日期的历史输入，不能冒充 2026-08-22 当前事实。

- **已证明／有界可继承**：固定 Hermes `v0.20.0`、SQLite 事务/备份、`cryptography` 与 systemd 一般原语；旧候选的单 subject 画像版本/current pointer、冲突降级为未知、untrusted 资料隔离、局部墓碑和受控 tmpfs 导出。
- **需要重新核验**：当前 Partner 资产与状态面、主人时区和控制状态、全部健康副本、外部快照、运行时 manifest、删除/恢复/迁移和业务观测 canary。
- **已经失效为当前权威**：旧四类画像结论、旧 personal evidence 子型、旧任务状态、viewer/recovery 控制、普通 Session/Memory/通用 backup 作为健康权威，以及全部 `ops/` 候选路线。
- **尚未实现／未证明**：当前六域拓扑和主题预算、三类证据卡与关系、四标签任务和批准、独立控制与当地日语义、全对象删除/防复活/空白重初始化、业务三态和完整迁移闭包。

## K06：六域画像、当前视图、更新与导出

Hermes Plugin 只能提供结构化 Tool/handler 扩展面，不能推出健康对象模型、主题批准、当前引用或跨对象提交（Evidence 23:5-8）。旧 sidecar 有一次 mutation 同时加入个人证据、不可变 profile version 并切换 `current_version_id` 的局部原语；这可作为修订和 current-head 的历史输入，不能代表当前六域画像（Evidence 22:91-94；Evidence 23:8-9,67）。

旧候选使用 `state/habit_goal/interaction_preference/task_context` 四类结论和全局摘要，不是当前顶部“当前状态”加六个固定一级领域及基础二级主题；资料库的六种 metadata 标签也不是六个健康领域。它没有固定主题拓扑、每主题明确未知、主题变更主人批准、趋势/开放判断/关键未知的结构化引用，不能满足当前画像合同（Evidence 23:11-13,68-71）。K06 的完整更新、纠正、撤回、失败/无法确认和非第二权威导出均未证明。

## K07：三类证据、关系、待澄清与历史窗口

旧候选可以区分少量 personal evidence 来源子型，可以保存来源时间、准入和最小摘录；通用资料卡可标记 `untrusted_data`，避免查询结果直接升级为个人事实或任务动作（Evidence 23:8-9,72-75）。冲突候选降级为待核实并阻止自动派生任务，是有价值的未知处理原语（Evidence 23:103-111）。

三种个人 evidence 子型不是现行三类一级卡；任务过程散落在 task/audit，没有独立“任务过程证据”卡。当前没有统一个人健康证据/通用权威知识/任务过程证据类型、六域索引、支持/反对/限定/实际使用/纠正/替代/撤回四类关系、待澄清不支撑结果、近期五张明细、保护例外和滚动摘要谱系（Evidence 23:11-15,72-77）。引用接受任意字符串，局部 ID 不足以证明没有悬空引用、双当前卡或跨类型自动转换。

## K08：任务候选、建档、阶段、批准、四标签与验收

旧候选任务可校验目的、证据 ID、时间、策略和 source card 当前性；dispatch 有有限尝试、跳过、失败和接口接受记录（Evidence 26:35-40,50-56）。投递账本能保留 `accepted/rejected/uncertain`，未知不盲重发，是局部交付事实。

候选任务状态仍围绕 `candidate/scheduled/due_for_render/sent/skipped/failed/cancelled`，不是当前互斥主标签 `active/solved/failed/cancelled` 与独立结果未知；`sent` 不能证明任务验收或主人行动。没有承担者、可判定验收、阶段权威、批准/撤回、前序/后继、同缺口查重，也没有四个 B 类职责只回候选、任务框架独占建档/阶段/验收/标签的可证明接口（Evidence 26:37-43,57-65）。未知送达被候选 dispatcher 强制落成任务 `failed`，与当前“active + 结果未知、不得自动重试”合同冲突（Evidence 26:59-63）。

## K09：当地日、时区、通知、投递未知与恢复

Hermes Cron 和旧候选能承载当地日计算、一次复盘和有限重试；固定 Cron 可区分 `completed/failed/unknown`，投递账本能阻止同键未知重发（Evidence 26:67-72；Evidence 14:13-15,21-29）。这些只证明可承载的调度/未知原语。

当前现场没有健康 Plugin、业务 Cron、健康任务账本或 outbox；`04:00` 计划表面不证明主人当地自然日复盘已执行。服务器时区或固定 `Asia/Shanghai` 也不证明主人时区，时区变化后的下一有效当地日、不补做/不堆积/不重复、最近复盘查询、无行动安静、五类普通通知和不可关闭必要结果均未证明（Evidence 26:74-81；Evidence 14:31-40）。

## K10：设置、独立控制、数据权利与真实提交

旧候选有查看、导出、暂停/恢复主动联系、停止/恢复记录和删除命令的局部访问校验；部分控制提交可返回 changed/confirmed 状态（Evidence 26:83-88）。但暂停主动支持和停止新增记录在候选中都会遍历全部未终结任务并改为 `cancelled`，违反当前相互独立控制；没有可信的单项任务取消/延期/调整和执行批准撤回语义（Evidence 26:41-43,90-97）。

删除候选增加十分钟确认窗、三十天备份清理和“永久删除”终态通知，属于当前产品明确排除的额外承诺。当前没有统一结果证明时区、通知、停止记录、任务取消、批准撤回、联系人控制、查看/纠正/导出/删除和运行状态各自独立，且只有权威提交后才称已生效。

## K18：全对象删除、防复活与空白重初始化

旧候选的 profile-key tombstone、删除当前状态、清理投影和受控临时导出是局部清理原语；完整删除必须覆盖全部可重新读取/恢复的本地健康对象和副本，旧代码+旧 key+旧状态的整体回滚也必须被阻止。当前没有全部副本清单、删除代际或删除后只能由主人主动 `health-init` 建立空白状态的证明（Evidence 05:40-60；Evidence 22:113-154）。

## K19：三态业务观测、故障隔离与转换通知

旧 operator monitor 能观察审计、每日复盘和 dispatcher 心跳并产生 firing/recovered 告警；固定 Cron/投递接口可产生局部 `completed/failed/unknown` 状态（Evidence 26:99-105；Evidence 14:61-70）。但 monitor 不读取画像、任务、控制、健康入口、模型、安全、问答或诊断范围的统一业务事实；合成测试允许 `production_acceptance=blocked` 时仍报告 `service_health=healthy`。业务三态、受影响能力、单项故障隔离和一次性转换通知尚未实现或证明。

## K20：完整迁移与单一当前权威

旧发布器能为一组 release files 生成 hash manifest，`restore_backup()` 能校验并替换主加密状态 blob；这只证明字节级发布/恢复候选（Evidence 26:115-129）。manifest 没有枚举全部七 Skill、共享规则、六域/三类证据、任务、批准、控制、未知、交付、删除代际及模型/诊断/联系人资产；审计、raw/cache、投递账本、projection、key、backup、export 和普通 Hermes 历史处于不同提交面。没有源端冻结、目标端单写接管、无双当前、批准/撤回/未发动作按迁移后当前性重判或失败/未知停止证明（Evidence 22:115-154；Evidence 10:80-105）。

## 结论与后继交接

本票形成负向但不降低 TO 的 CAN 结论：固定平台和历史候选给出若干可复用原语，正式 Partner 当前没有可验收健康状态对象；旧候选存在确定性合同冲突，不能被拼接成当前 HOW。Ticket 106 继续核验模型/医学/诊断对象和 K14 可信危险集成；Ticket 107 核验联系人/批准/警报/交付对象。正式删除、恢复、时区、故障或迁移实验仍须另行批准。
