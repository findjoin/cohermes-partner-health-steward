# Ticket 106 首跳隔离、医学治理、诊断完整性、安全与修订核验（2026-08-22）

## Answer

K11—K15 以及诊断侧 K18—K21 的结论是**负向但可判定的 CAN 结果**：固定 Hermes 提供 Plugin 的 out-of-band 模型调用、结构化候选、Tool/Skill 扩展和本地校验等一般原语；历史现场能够定位 2026-08-20 当时磁盘声明的名义首跳，历史医学 Evidence 能命名 BMI 与疑似原发性高血压两个可审计候选。但当前 Partner 没有可定位的健康路由、主人同意快照、医学内容权利/版本/审核闭包、诊断完整结果对象、可信危险规则集成或诊断修订链。当前可证明的激活诊断范围仍为 0。

本票不选择 provider、模型、搜索服务、医学来源组合、诊断范围、规则引擎、状态机、存储、部署或其他 HOW；也没有发送模型/搜索/微信请求，没有读取真实健康资料、聊天、联系人、密钥、Token、服务器配置、运行数据库或生产日志。

## 证据层级与分类

- **已证明／可有界继承**：Hermes `v0.20.0` 固定提交提供 `ctx.llm` 的 out-of-band 调用、Plugin 自有输入构造、Tool/Skill 注册和局部结构化/来源 ID 校验原语；公开医学来源可以支持术语、指南、患者解释、文献发现或药品标签等不同职责；历史现场可定位名义 provider/endpoint/model/API mode（Evidence 24、Evidence 11、Evidence 12、Evidence 16）。
- **需要重新核验**：2026-08-20 的名义首跳是否仍是当前 Partner 实际配置、健康是否已部署、首跳同意/变更暂停、当前搜索和 Tool 出口、当前来源版本与权利、医学审核、规则失效、模型完整终态和业务结果事实。旧现场日期早于 2026-08-22，不能冒充当前运行事实。
- **已经失效为当前权威**：旧 sidecar 的 pinned endpoint/no-fallback、按主人消息选择 URL 的回源、旧 `health-guard` 关键词、旧 `medical` Skill、旧八张来源卡/自由文本回答 schema、画像 `current_version_id` 和全部 `ops/` 候选路线。它们只能作为反例或局部原语输入。
- **尚未实现／未证明**：路线变化先暂停并重新同意；主人派生查询路线外隔离；有依据非诊断问答的类型化结果和最小留存；医学内容权利/冻结版本/专业审核/撤回；诊断资料、容量、完整终态和临时清除；可信危险五态收敛；单一诊断当前与修订/纠错；诊断对象纳入删除、三态、迁移和未来验收闭包。

## K11：首跳路线、出站隔离与有依据非诊断问答

固定 Hermes 的 `ctx.llm` 不自动创建普通 Session/FTS/Memory，Plugin 可以自行构造最小输入；这是可承载的历史隔离原语，不是当前健康链证明（Evidence 06、11、24）。2026-08-20 的脱敏现场曾把名义首跳记录为 provider `jojo`、`https://max2.jojocode.com/v1`、`codex_responses`、请求模型 `gpt-5.6-sol`，但那只是早于本票日期的磁盘/进程配置快照。Hermes Plugin API 没有 endpoint、禁用 fallback、route preview、完整 recipient allowlist 或发送前最终接收方回调；JOJO 公开资料还描述动态路由/故障转移。因此 provider 名称、名义 endpoint、结果中的 model 或顶层没有 fallback 字段，均不能证明发送前已锁定全部接收方或主人已同意。

当前 Partner 没有可定位的健康 Plugin、健康初始化状态、路线同意快照、路线变更暂停点或本地权利继续执行链。旧候选按主人消息关键词选择 URL 并在缓存 miss 时 HTTPS 回源，是确定的主人派生查询反例；静态白名单、去姓名、无 query 参数、缓存命中或延迟执行都不会把它变成独立通用更新（Evidence 24）。旧候选的八张来源卡上限、ID allow-list、无正文 delivery ledger 和 pinned client 只能证明局部边界，不能证明当前六域/三类证据问答、路线外隔离、诊断越界转交、业务提交、发送和主人到达。

**K11 判断**：固定扩展面和历史局部隔离原语已证明；当前首跳同意、全接收方锁定、路线外查询隔离、类型化非诊断结果、最小留存和分层交付尚未实现或未证明。普通 Agent、普通 Tool、旧回退和旧回源路径不能升级为当前权威。

## K12：医学内容治理、范围候选与失效入口

Evidence 12、25、27 证明不同来源承担不同职责，不能拼成一个无条件“医学知识库”：国家卫生健康委中文指南可提供特定规则候选；NICE 可提供另一套成人高血压建议及版本入口；WHO ICD-11 MMS 主要承担术语/编码；WHO CDDR、患者教育、PubMed、DailyMed/openFDA 各有职责边界。公开页面、指南版本和中文材料不等于本项目取得 AI/生产复用、改写、规则化或再发布权。

两个实质不同候选已形成可审计负向研究：

- BMI 候选：成年、非妊娠且测量可靠时仅作 BMI 超重/肥胖及程度辅助分类；中文指南和阈值入口成立，但内容权利、冻结清单、专业审核、激活/撤回/过期执行均未闭合（Evidence 25）。
- 疑似原发性高血压候选：需要跨日/跨场景测量、设备与质量、白大衣/隐蔽性、严重数值—急性症状/体征分流和医生专属范围外处理；中国 2025 来源与 NICE 2026 来源存在实质规则差异，权利、版本选择、项目审核和失效退出均未闭合（Evidence 27）。

因此，当前不能把任何候选标为 active，也不能把来源更新、撤回、过期、规则冲突、范围外或安全不可用写成已执行状态。**K12 判断**：有一手来源和有名候选的审计入口已证明；内容权利路线、中文版本冻结、专业审核、范围激活、撤回/过期观察和失效出口尚未实现或未证明。

## K13：诊断资料选择、容量完整性、结构终态与最小留存

固定 Plugin 可以自行构造输入并在本地做结构校验，旧候选可以限制摘要、证据 ID 和来源卡数量；这些是承载面，不是完整诊断合同。旧回答 schema 只有 `answer_text` 与 `used_source_card_ids`，不能强制表达个人事实/医生转述/AI 判断分离、支持与反对证据、关键未知、紧急程度、安全下一步、不确定性和诊断边界。旧上下文在必要资料超过八张时静默截取，不能把“ID 可引用”当作资料完整性。

固定 `codex_responses` 适配器不把 `max_tokens` 可靠转换为输出上限，也不透传结构化 `response_format`；Responses 的 `incomplete`、`failed`、`incomplete_details`、response id 和部分流无终态信号会在归一化中丢失或被表现为普通 `stop`（Evidence 16、24）。现场 `context_length: 240000` 只是 Hermes 配置值，不是所有正常/故障路线的共同窗口；粗略 token 估算、事后 usage、非零正文或接口接受不能证明输入未截断、输出完整或最终模型固定。

当前没有诊断结果对象、范围注册、最小资料选择、完整终态回执、部分/截断候选拒绝提交或临时资料闭合清除的证明。真实模型、真实健康资料和故障注入均未执行，也不需要用一次成功请求掩盖静态合同缺口。**K13 判断**：Plugin/本地校验原语已证明；诊断输入完整性、共同容量、结构化终态、失败关闭、最小留存和不发送部分结果尚未实现或未证明。

## K14：可信危险治理与独立最低安全路径的集成

Ticket 104 已将“独立于 Skill/steward 的最低求助结果”作为单独边界，但其生产加载、真实可用性和主人到达仍未证明。本票只补可信危险规则与诊断链的集成：只有来源/版本/专业审核成立、当前范围适用且个人证据足以确认的危险，才可形成联系人最小警报候选；危险未明或安全能力不可用只能给主人固定最低求助结果，不能外发联系人、不能伪造 Skill 使用、不能形成诊断/画像/普通任务结果。联系人对象交给 Ticket 107。

旧 `health-guard` 的关键词、固定文案和 Hook/transform 候选只证明局部拦截空间。关键词会误报/漏报，旧入口不检查当前 `health-init`，旧名包含 `medical`，Hermes Hook/Middleware/Plugin 异常也不能自动 fail-closed；仓库没有可定位的五态（范围内、范围外、危险升级、危险未明、安全能力不可用）统一收敛、候选专属严重阈值—症状/体征规则、来源失效传播或分层业务结果（Evidence 06、12、25、27）。

**K14 判断**：独立最低安全合同和“可信危险才产生联系人候选”的产品边界已明确；可信规则治理、诊断集成、不可绕过的五态收敛、故障时固定结果和零健康副作用尚未实现或未证明。未知危险不得被普通补问、关键词未命中或模型自由文本升级为已确认危险。

## K15：诊断修订链、依据失效、单一当前与必要纠错

旧画像一次 mutation、不可变 profile version/current pointer，以及资料卡 `current/superseded_by` 关系是可复用版本原语，但它们不是诊断对象的修订链。当前没有同一问题/事件/时期的诊断记录、至多一个可证明当前或明确无当前、医生结论与 AI 判断分离、依据撤回/过期传播、权威未知停止、无变化复核、替代/降级/撤回或一次必要纠错通知（Evidence 25、27、32）。

特别是，单条血压解析写入 `measurement.blood_pressure.latest`，不能替代跨日测量序列、冲突证据、医生转述和危险分支；来源卡 superseded 也没有向诊断判断传播失效。并发提交、崩溃恢复、主人纠正、医生结论冲突和纠错到达均未被当前 Partner 证明。**K15 判断**：版本指针/后继关系局部原语已证明；诊断单一当前、修订原因、依据失效传播、未知停止和一次纠错闭包尚未实现或未证明。联系人侧纠正发送由 Ticket 107 接续。
